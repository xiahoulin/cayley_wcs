# WMS 到模拟堆垛机故障回传与原始 OPC UA 协议核查

当前48项号码均可从模拟堆垛机经真实OPC UA传到WMS任务，但只传首个非零号码；完整故障数组、故障名称与级别，以及设备空闲时的报警未进入WMS。因此号码传递通过不等于所有故障信息都已完整对接。当前协议也不能判定完全符合最初资料。

本次使用当前Docker镜像和真实业务接口，完成48项逐项故障、3项数组场景、1项执行中故障、设备空闲报警、心跳冻结及无故障恢复实验。生产业务代码及镜像没有改动；测试单据、托盘和任务记录保留。测试结束后恢复原堆垛机端点、应用固定协议版本与运行配置，独立探针已停止。

## 实际链路与结果

WMS管理接口先生成待派工的设备业务任务；调度器使用应用访问令牌，将业务点位放在请求点位对象 payload 下发WCS。WCS使用PLC4X客户端与Eclipse Milo服务端交换真正的OPC UA数据。设备数组中的首个非零号码成为任务故障码 error_code，WMS通过任务回调或查询对账保存该号码。

| 场景 | 实际结果 |
| --- | --- |
| 原资料1–48逐项注入 | 48/48号码与WMS保存值一致；39项由回调先落库，9项由查询对账先落库 |
| 60槽数组末槽故障28 | JSON下标59的28能够读取并传到WMS |
| 下标17为18、下标59为8 | WCS记录两项报警，WMS任务只保存18，完整数组没有进入WMS |
| 下标0为正常提示48、下标59为故障18 | WMS只保存48，任务判失败；正常提示还遮住了后面的真实故障 |
| 堆垛机已经执行时再注入18 | PLC任务状态为1且远端已开始物理执行；WMS任务63最终failed/error_code=18，库存不变 |
| 空闲设备故障24 | WCS实际投递报警通知；WMS验签后返回skipped，不创建或保存设备报警 |
| 可见PLC心跳冻结超过30秒 | WCS仍RUNNING，活动时间持续更新，未触发通信报警；默认超时为12秒 |
| 无故障恢复上架 | WMS任务62与远端102104完成，60槽为0且采集质量good；入库30只新增1条库存流水、过账1量 |
| 重复失败回调及报警通知 | WMS保留既有故障结果；库存流水没有再增加 |

52个失败任务对应的库存操作均为FAILED，没有遗留活动范围锁；原生设备任务号占用已清理，设备空闲、故障清零，连接恢复为RUNNING/good。

## 与最初 OPC UA 资料的符合情况

原始[堆垛机通讯协议](../堆垛机通讯协议-opcua对接版.xlsx)的27个字段名称、方向及符号映射全部对应，60元素Int16故障数组正确，48项文字释义相符。正常参数写入顺序、确认1→0→2以及命令清零相符。独立探针经真实OPC UA读取全部27节点的类型、维度、访问位及值类型，27/27通过。

| 问题 | 当前差异 | 处理方向 |
| --- | --- | --- |
| PLC心跳停滞检测 | 仅通信读成功就刷新活跃时间，未检查PLC心跳是否变化；实测已复现 | 区分通信可用与PLC程序活跃，按心跳变化时间检测超时 |
| 48正常复位消息 | 字典级别为info，仍按非零故障阻塞并判失败；实测已复现 | 将正常状态消息与阻塞故障分开，选择故障码时避免正常消息遮住真实故障 |
| 任务号原生类型 | 原资料写INT但范围到65534；仿真用UINT16，物理协议仍INT16草稿 | 依据现场PLC节点确认有符号/无符号类型，统一取值范围后发布；不可直接把仿真类型当现场类型 |
| 请求/反馈类型3与4 | 原资料请求3为移库、4为移动，反馈3为移动、4为转库；模拟器直接复制请求，且反馈扩展到6 | 确认PLC反馈枚举后修正模拟器及协议约束 |
| 模拟PLC心跳周期 | 目前每1秒翻转，原资料要求5秒 | 使仿真节拍与原资料一致，再覆盖超时边界 |

现场NodeId命名空间和命令任务号的回读访问权仍需依据实际PLC节点确认，原资料没有给出足够信息，不能仅凭模拟器保证。详见[完整点位与故障定义对照](2026-10-13-stacker-opcua-conformance.md)。
