# 应用和协议安全删除

任务：TASK-20261112-A9BE6E99。

管理接口仍为 `POST /application/delete`、`POST /protocol/delete`，请求为 `{"id":...}`，保留现有权限和固定租户检查。资源不存在或不属于当前租户返回业务码 404；存在依赖返回 409 和中文原因。前端在确认前展示永久删除及清理范围。

## 删除范围

| 入口 | 在同一数据库事务中删除 |
|---|---|
| 应用 | 全部所属协议，包括退役/停用版本；协议点位、发布版本、故障码及相关迁移审计；应用令牌、看板偏好、日志、告警、设备任务号游标；已结束的相关回调投递记录；传感器关联；无其他应用使用且已停用的自有网关及其最新值/采集历史 |
| 协议 | 目标协议的全部点位、发布版本、故障码和迁移审计，最后删除协议 |

解除应用的协议选择、解除协议的发布版本选择，再按子记录到父记录的顺序删除；保留 V25 的数据库外键约束。单独删除一个传感器应用保留其他传感器、共享网关及共享采集历史；只有最后删除无依赖的 AGV 自有网关时才清理网关历史。

## 禁止删除

- 任意任务使用应用作为执行方或调用方，或固定目标协议的发布版本。完成、失败、取消、软删除的任务同样属于历史引用。
- 任意授权记录引用应用或版本，包括停用、撤销和软删除记录。撤销权限不等于移除历史引用；本接口不自动抹除授权或任务。
- 任意任务链的调用方、直接设备、候选设备、固定版本或原始段定义引用目标，终态链同样受保护。格式损坏而无法确认引用的关联记录拒绝删除。
- 协议仍被应用选用；应用连接未关闭或有设备任务号占用。
- AGV 网关仍由其他传感器应用使用，或采集尚未停止；删除独立传感器前，其共享网关的全部传感器连接须关闭。
- Webhook 配置明确包含该应用，或该应用存在待投递回调。不能把唯一应用范围自动删为空列表，因为空列表表示所有应用，会扩大回调范围。

## 并发与缓存

V26 增加 `wcs_resource_lifecycle_lock` 单行锁表。PostgreSQL 引用写入使用 `FOR SHARE`，可并发；删除使用 `FOR UPDATE`，等待既有写事务结束，检查到最新依赖后才删除。新任务、链、授权、发布/点位、采集配置、应用令牌、看板偏好及后台事件写入共用该锁。H2 测试使用其支持的独占行锁。

所有缓存副作用在数据库提交后执行；回滚不关闭采集、不失效故障缓存、不删除重放保护。清理仅针对目标协议、网关及 AppKey，保留其他应用缓存和用户登录令牌。Redis 失败会进入后台重试；重放键本身仍有有效期，已删除的应用身份立即无法通过鉴权。迟到的日志/告警/采集记录不会重新生成孤立数据库行。

## 验证

`ResourceDeletionTest` 使用实际 Spring 服务、完整 Flyway 和真实事务，覆盖级联、保留其他资源、阻止历史引用、回滚、跨租户及两个并发顺序。当前 PostgreSQL 的备份在独立副本升级 V26，核对既有数据和版本不变，再验证 API 与真实 Redis 清理。生产部署只升级应用镜像和 V26，不对现有六个业务应用执行删除测试。
